# 私董会顾问团：点名发言 + 执行主笔落盘

- **适合**：想用几只人设顾问帮你挑毛病，又怕群聊刷屏烧额度、顾问互相改文件的人
- **详细教程**：[grokguide.si/tutorials/advisor-board](https://grokguide.si/tutorials/advisor-board)
- **思路来源**：[Martin（小马）@xiaomanotes《我给 Grok Bot 搭了个私董会》](https://x.com/xiaomanotes/status/2117059760646443186)

## 场景

一篇复盘稿自己读两遍也看不出前后数字打架；单 Bot 很少质疑自己刚写的东西。想拉几位立场不同的顾问进群，但群里每条 Bot 回复（含 Bot 互发）都计额度。

## 准备

- 四位顾问人设（只建议、不碰文件）+ 一位执行主笔（改稿落盘）+ 人最终拍板
- 每轮写清「这次只要谁说」——用 @ 点名，未点名的保持安静
- 共享审稿稿或草稿路径；顾问 description 写死 `may_touch_files` 等价约束：不改正文、不删文件
- **不要**把顾问写成也能改稿的第二主笔

## 步骤

1. 先定原则：顾问只发言，执行主笔写，人拍板。
2. 为每位顾问写清角色、什么时候该开口、哪里停下（不落盘）。
3. 执行主笔：收顾问意见 → 改稿/落盘 → 回群报一句结论。
4. 每轮开头点名：例如「本轮只 @留存顾问 @渠道顾问」。
5. 意见打架时，人说「这个不改 / 这个改」；不要让顾问互刷到底。
6. （可选）用本地巡检脚本核对：顾问不可碰文件、草稿数字是否自洽、本轮开口人数。

## 提示词

```text
请按「私董会顾问团」起草花名册草案（先草案，不要新建 Bot）：
顾问四人：狠话 / 热点 / 留存 / 渠道（可换成你的领域）。
每人写：角色、什么时候开口、硬停下（不碰文件、不改正文）。
另设执行主笔：可改稿落盘，每轮收口后回群报一句结论。
原则：advisors_speak_executor_writes_human_decides。
每轮必须写清点名名单；未点名顾问保持安静。
额度提醒：群里每条 Bot 回复（含 Bot 互发）都计用量。
```

## 产出

顾问花名册 + 执行主笔合同 + （可选）矛盾巡检脚本与一版改后草稿。

## 注意事项

- 群聊额度按回复数算；顾问越多、越全开，烧得越快。
- 描述拦的是意愿：同机 Bot 仍共用云电脑文件——所以顾问合同要写「不碰文件」，关键稿仍由执行主笔单一写入。
- 模型路由交给平台；你花时间写清楚角色比纠结背后是谁更划算。
- 本账号无 cloud agents 时，不要假装派过云端编程 Agent。

## 小伟点评

虚构播放复盘草稿：总览完播 4820、分表加总 3650；本轮只点名留存+渠道，预估 3 条 Bot 回复；ASSERT_OK。
