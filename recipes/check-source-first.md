# 先查来源：会变的事不只信记忆

- **适合**：Bot 记住的日期、邮箱、订单状态过期了还在照着用的人
- **详细教程**：[grokguide.si/tutorials/check-source-first](https://grokguide.si/tutorials/check-source-first)

## 场景

会议改期、联系人换邮箱、订单状态更新以后，Bot 还按记忆里的旧值回答。让它记住“去哪查”，每次回答前先查。

## 准备

- 列一张表：每个 Bot 用到哪些会变的事实，各以哪里为准（日历、邮箱、表格、数据库）
- 这些来源 Bot 都能打开

## 步骤

1. 让 Bot 列出会变的事实和对应来源，每个来源实际打开一次。
2. 记忆里具体的值改成“去哪查”，旧值有用的留成带日期的历史。
3. 加一条规矩：先查来源、说明出处、查不到就直说。
4. 先改一个 Bot 给你看，同意后再推到其他 Bot。
5. 抽查三个 Bot，各问一个会变的事。

## 提示词

```text
帮我给所有 Bot 立一条规矩：会变的事先查来源，不只信记忆。
发送、付款、发布这些权限保持不变，照旧要我点头。
1. 列出每个 Bot 用到的会变的事实（日期、价格、状态、联系方式、余额、订单）和各自以哪里为准，每个来源实际打开一次。
2. 不变的偏好留着；会变的事实，记忆里只写去哪查，旧值改成带日期的历史。
3. 回答会变的事之前先查来源，说明查的是哪里；查不到就直说，不拿记忆里的值顶上。
4. 先拿一个 Bot 改，把改动列给我看，我同意以后再改其他的。
5. 改完抽三个 Bot，各问一个会变的事，看它们是不是去查了。
```

## 产出

一张“事实 → 来源”对照表，改过的记忆，以及每次回答都带出处的 Bot。

## 注意事项

- 只有会变的事才去查，偏好和规矩照旧用记忆，免得白耗额度。
- 来源需要登录时你来接手输入，别把密码发进聊天。
