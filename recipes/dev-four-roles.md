# 研发四个角色：需求、复现、实现、审查

- **适合**：让 Bot 参与写代码的团队
- **详细教程**：[grokguide.si/playbooks/engineering-bot-fleet](https://grokguide.si/playbooks/engineering-bot-fleet)

## 场景

写代码的 Bot 自己说“能合”，等于自己批自己的作业。

## 准备

- 代码仓库和问题跟踪工具的权限
- 一份验收口径

## 步骤

1. 需求 Bot 读问题，写成规格，状态只有：待批准、缺信息、卡住。
2. 你点名批准某一版规格，Bot 之间的交接不算批准。
3. 复现 Bot 写出复现步骤或一个会失败的测试。
4. 实现 Bot 只按批准的规格改代码，说明改了什么、怎么验证。
5. 审查 Bot 在单独对话里只看提交，给出通过、阻止或缺证据。
6. 你看审查结论，自己合并。

## 提示词

```text
你是审查 Bot。只根据这份提交 {{链接}} 和已批准的规格 {{规格版本}} 判断。逐条对照验收条件，每条给出证据（命令输出或截图）。最后只输出三种结论之一：通过、阻止（写原因）、缺证据（写缺什么）。不要修改代码，不要合并。
```

## 产出

每个提交一份带证据的审查结论。

## 注意事项

- 审查 Bot 不能和实现 Bot 在同一个对话里。
- 没有验收条件就别开工。
