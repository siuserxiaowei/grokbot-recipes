# 工程 Bot 小队：共享进度表巡检 + 夜间审计

- **适合**：想按领域拆两三只工程 Bot，用一张进度表盯 PR，夜里再跑一项审计，又没有（或不想假装有）cloud agents 的人
- **详细教程**：[grokguide.si/tutorials/eng-bot-fleet](https://grokguide.si/tutorials/eng-bot-fleet)

## 场景

官方工程指南里，专责工程 Bot + 共享看板每 30 分钟巡检 + 夜间审计，能把大量 PR 推到「待审」。我们这边用职责卡、进度表字段和本地巡检脚本把同一套结构落地；合并仍等人点头。

## 准备

- 2–3 只工程 Bot（或先从一只开始）+ 可选运营协调
- 一张共享进度表（表格 / 看板 / 仓库 CSV 均可）：状态、CI、冲突、备注
- 明确：巡检只改状态和建议；不自动合并；P0 临时例行用完就关

## 步骤

1. 写职责卡：管什么、不管什么、跨域怎么交接。
2. 进度表每行一个 PR；状态用 Working / Ready for Review / Blocked。
3. 约每 30 分钟巡检 Working 行：CI 失败、冲突、待核实评论 → 改回 Working 并追负责人（或 cloud agent）。
4. 全过才标 Ready，建议审码；不自动合并；没变化打 quiet。
5. 夜间六选一先开一条（清库 / 安全 / CI 时长 / i18n / 多端 / 补漏）。
6. P0 才开「每五分钟看一眼」，用完关掉。

## 提示词

```text
你负责巡检共享进度表里状态为 Working 的行，大约每 30 分钟一次。

对每一行检查：CI 是否失败、是否有合并冲突、备注里是否有待核实的机器人或安全评论。
- 有问题：把状态改回 Working，排队通知负责人（或正在跑的 cloud agent），写清要修什么。
- 全部通过：标 Ready for Review，并建议启动一轮审码；不要自动合并。
- 没有变化：只打一行 quiet，不要刷屏。

不要对外发送，不要改生产，不要动钱。
```

夜间审计示例（CI 时长）：

```text
今晚只做一项夜间审计：CI 构建时长。
对比各工作流「今日中位」和「近 7 日中位」，差值 ≥ 5 分钟的列入报告，并建议开排查 PR 的方向。
只交早上清单，不要自动开 PR，不要自动合并。
```

## 产出

职责卡草稿 + 巡检动作清单（要追的 / 可待审的 / quiet）+ 可选夜间审计报告。

## 注意事项

- Routine 说明写「共享进度表 / cloud agent」，别写死某家看板或 API 名。
- 没有 cloud agents 也能用：追进度表上的负责人即可。
- P0 临时高频例行很费额度，只紧急用。
- 官方小范围自动合并是他们的取舍；我们默认待审后人合并。

## 小伟点评

虚构 6 行进度表实跑：2 条要追（CI 失败、冲突），2 条可待审，2 条安静。夜间 CI 时长审计揪出 desktop-ci、e2e-smoke 两条变慢。结构能抄，头衔不用抄。
