# 重复任务扫描：两周日志里找出该自动化的三件事

- **适合**：觉得一天很忙却说不清时间花在哪，想先挑三件重复活交给 Bot，又不想一口气开一堆自动化的人
- **详细教程**：[grokguide.si/tutorials/repeat-task-scan](https://grokguide.si/tutorials/repeat-task-scan)

## 场景

邮件整理、会前简报、抄表、FAQ、状态回复……很多活每周都在做，但很少被写成 Routine。先让 Bot 扫过去两周，只交「出现两次及以上」的清单和 Top3 建议，你再决定开不开。

## 准备

- 一个主 Bot（或工作向 Bot）
- 能读邮件 / 日历 / Slack / 文档的只读连接（没有连接器时，可先用导出表或粘贴的事件列表）
- 明确：只出建议，不私自新建自动化

## 步骤

1. 划窗口：过去两周；渠道写全。
2. 只留重复：同一任务 ≥2 次；一次性丢掉。
3. 写清次数、均次耗时、合计；标可代做程度。
4. 按估算可省时间取 Top3：Routine 还是专用 Bot。
5. 你批准后再开；对外发送、付款照旧问你。

## 提示词

```text
请扫描我过去两周的工作：邮件、会议、Slack、文档，以及你能看到的其他记录。

找出我做过两次及以上的任务，按类型分组。对每一项写：
1. 一句话任务名
2. 次数
3. 均次大概多久、两周合计多久
4. 你能否部分或大部分代做，以及需要什么只读权限

再按估算可省时间排出优先自动化的前 3 件：每件建议做成 Routine 还是专用 Bot，并写清完成后的验收标准。

只交建议清单。不要新建 Routine，不要改现有自动化，不要对外发送。
如果两周里没有明显重复，就写「暂无优先项」。
```

## 产出

一份重复任务表 + 优先自动化 Top3（形态建议与所需只读权限）。

## 注意事项

- 一次性任务不要硬塞进表。
- 可省时间只作排序，不是承诺；你自己的节奏为准。
- 没有连接器时，先用导出/粘贴列表练同一套规则。
- 对外发送、改生产、动钱，一律等你批准。

## 小伟点评

虚构 32 条两周日志实跑：5 项重复入表，改页脚一次性被丢掉；Top3 是收件箱整理、会前简报、周报抄表。先跑稳三件，再拆下一件。
