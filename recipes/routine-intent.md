# Routine 只写意图：别把工具名写死

- **适合**：Routine 里写过具体 MCP 工具名，接口一改就整条挂掉的人
- **详细教程**：[grokguide.si/tutorials/routine-intent](https://grokguide.si/tutorials/routine-intent)

## 场景

定时任务里写死了 `slack_send_message` 这类工具名。连接器升级或改名之后，同一条 Routine 突然找不到工具。改成只写要达成的结果、约束和同步去向，具体调哪个工具留给 Bot 每轮自己查。

## 准备

- 一条已经在跑、或准备新建的 Routine
- 当前连接器 / MCP 工具列表能打开（设置里能看到即可）

## 步骤

1. 打开这条 Routine 的说明，划出所有工具名和固定参数名。
2. 改写成三段：要达成什么结果；约束与语气；需要同步到哪里。不要出现具体工具名。
3. 补一句：具体用哪个工具，每轮先查当前可用工具再选；找不到合适的工具就报失败，不要猜。
4. 用「工具改名」场景测一遍：人为假设旧名已不存在，看它会不会换到新名，还是直接报错。
5. 手动跑通后再存成 skill；对外发送仍然等你批准。

## 提示词

```text
帮我把这条 Routine 改成只写意图，不要写死工具名：
1. 先读我贴上的旧说明，列出里面出现的工具名和参数名。
2. 改写成三段：要达成什么结果；约束与语气（语言、长度、能不能直接发）；需要同步到哪里。
3. 文末加一句：具体用哪个工具，每轮先查当前可用工具再选；找不到合适的就告诉我“这次没做成”，不要猜、不要沿用旧工具名。
4. 给我新旧对照表，以及一段我可以直接贴进 Routine 的新说明。
5. 不要改任何已启用的 Routine，等我说“按这个改”再动。
```

## 产出

新旧对照表、一段可粘贴的意图式 Routine 说明。

## 注意事项

- 意图里仍然要写清“只起草、等批准”这类边界，别把发送权放开。
- 工具列表为空或连不上时，应报失败，不要假装成功。
- 和“固定步骤交给脚本”不冲突：机械检查可以走脚本；需要判断和选工具的部分写意图。

## 小伟点评

虚构两条 Routine、两版工具表实跑：写死 `slack_send_message` 的在改名后直接失败；只写意图的自动选到 `slack_post_message`，两版都通过。
