# 脚本先跑：固定的活交给脚本，Bot 只看一行结果

- **适合**：Routine 每天巡检页面或清单，没变化也要一页页看、额度掉得快的人
- **详细教程**：[grokguide.si/tutorials/script-first](https://grokguide.si/tutorials/script-first)

## 场景

巡检链接、比对清单、数条目这些活，每次步骤一样，用不着 Bot 一步步点。让云电脑上的小脚本跑完只打印一行 JSON：没变化 Bot 回一句就收工，有变化它才去看那几条。

## 准备

- 一件步骤固定、结果能和上次比的活，比如几个页面、一份清单或一个文件夹
- Bot 能用云电脑跑 Python（只用自带库即可）

## 步骤

1. 让 Bot 在云电脑上写一个小脚本，逐个检查来源、把状态记进文件、和上次比。
2. 约定脚本最后一行只打印 JSON：checked、changed、failed、needs_bot、ask。
3. 只报新出现的变化和失败，老问题不重复报；脚本出错也要打印一行写清原因。
4. 跑三次：建底一次、没变化一次、你改一处之后一次，看原始输出对不对。
5. 存成技能：needs_bot 为 false 就收工，为 true 才判断并用两三句话告诉你。
6. 最后挂 Routine，先一天一次。

## 提示词

```text
帮我把一件固定的活改成“脚本先跑，你只看结果”：{要巡检的东西}
1. 在云电脑上建一个文件夹，写一个只用 Python 自带库的小脚本，逐个检查来源，把状态记进文件，和上次比。
2. 脚本最后一行只打印一行 JSON，字段包括 checked、changed、failed、needs_bot、ask。只报新出现的变化和失败，老问题不重复报；出错也要打印一行 JSON，写清哪一步失败。
3. 脚本只读，不发消息、不删文件、不改外面的任何东西。
4. 跑三次给我看：建底一次、没变化一次、我改一处之后一次，贴原始输出。
5. 我确认以后存成技能：先跑脚本，needs_bot 是 false 就回一句“没变化”收工，是 true 才看那几条，再用两三句话告诉我。
6. 最后挂 Routine，先一天一次。发送、删除、付款照旧要我点头。
```

## 产出

一个只读的小脚本、一份状态文件、一个“先跑脚本再判断”的技能，以及一条低频 Routine。

## 注意事项

- 要看内容才能下结论的活（比如文章好不好）不适合全交给脚本，脚本只负责抓取和数数。
- Routine 每次还是会叫醒 Bot，省下的是醒来之后的活；频率本身也要从低开始。
- 思路参考 [grok-bot-local-first](https://github.com/MarkusIsaksson1982/grok-bot-local-first)。
