# 共享云电脑护栏：敏感只读别和能外发的 Bot 混装

- **适合**：一台云电脑上跑多个 Bot、其中至少一个能读敏感数据、另一个能发 Slack / 邮件 / 社媒的人
- **相关教程**：[幕僚长 Bot（文内护栏提醒）](https://grokguide.si/tutorials/chief-of-staff)、[隐私与安全合集](https://grokguide.si/topics/collection-privacy)

## 场景

2026-10-19 前后有公开报道：同一台机器上，一个只读银行余额的 Bot 和一个能发 Slack 的 Bot，敏感数字经工具流进了聊天。根因不是「Bot 变坏了」，而是**共享云电脑本来就不是隔离沙箱**——文件系统、部分工具上下文可以跨 Agent 可见。

## 准备

- 列出你账号里每个 Bot：连接了哪些应用、是否能外发、是否读财务 / 身份 / 密钥类来源
- 可选阅读（只读、不要照着复现攻击步骤）：[themsquared/grok-bot-cross-agent-leak](https://github.com/themsquared/grok-bot-cross-agent-leak) 与作者长文

## 步骤

1. **画一张花名册。** Bot 名、敏感只读（是/否）、能外发（是/否）、所在电脑（同一台？）。
2. **拆机。** 凡是「敏感只读=是」且「能外发=是」落在同一台电脑上的组合，拆开：敏感 Bot 单独一台，或外发 Bot 换机。
3. **收窄 Always Allow。** 发送、付款、删除类动作不要 Always Allow；外发默认要你点头。
4. **敏感输出打标。** 若你自建 MCP / 网关，对余额、账号、密钥类字段加敏感标记，禁止流入发消息工具（思路见上述护栏仓，不要复制其复现脚本）。
5. **定期复查。** 新接连接器或新加 Bot 后，再跑一遍花名册。

## 提示词

```text
请只读整理我当前 Bot 花名册（我贴名单，或你只读列出来的）：
1. 每个 Bot：名字、是否接了财务/身份/密钥类来源、是否能发 Slack/邮件/社媒、是否与其他 Bot 共用同一台云电脑。
2. 标出「敏感只读 + 能外发 + 同机」的危险组合。
3. 只给拆分与收权建议，不要自动断开连接器、不要复现任何泄露步骤、不要打印真实余额或密钥。
```

## 产出

一张危险组合表 + 拆机 / 收权建议。不含任何攻击复现步骤。

## 注意事项

- **不要在生产环境复现泄露 PoC。** 公开仓若附带复现脚本，仅作安全研究对照；本配方只采纳「护栏意识」。
