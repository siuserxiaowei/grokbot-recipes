# 每周功能对照：让首席 Bot 对照更新日志改你的 Routine

- **适合**：已经开了一批 Routine、怕绕路和额度浪费、想跟着官方新功能收紧流程的人
- **详细教程**：[每周功能对照：让首席 Bot 对照更新日志改你的 Routine](https://grokguide.si/tutorials/weekly-feature-check)

## 场景

官方 Changelog 几乎每周都动 Auto-review、连接器和 Routine 上限。你若自己一条条翻，容易漏；若让 Bot 直接改配置，又容易越权。做法是：固定一个「首席」Bot，每周只读官方来源，把新功能映射到你现有 Routine，**只交提案表，绝不擅自编辑、暂停或删除**。

## 准备

- 至少一个已经在跑的 Routine（例如工作日定时巡检、邮箱触发、来信摘要）
- 官方来源书签：https://x.ai/changelog/bot 、Grok Bot 文档（docs.x.ai/grok-bot）
- 可选：把首席 Bot 的职责写成「只提案、等你点头」的规则，并保留一份变更日志文件

## 步骤

1. **圈定时间窗**。告诉 Bot 对照「过去约七天」的官方 Changelog（或你指定的起止日期），忽略第三方转述。
2. **列出你的 Routine 清单**。名称、触发、主要连接器、最近是否卡在审批或额度上——由你贴，或让 Bot 只读列出后你确认。
3. **逐条映射**。对每条新功能问：它是否能缩短现有流程、减少无审批、或替换某步手工操作？标出「已全量 / 仍在灰度 / 需版本」。
4. **只出提案表**。列：功能、版本与链接、相关 Routine、建议动作、风险、是否需你确认。默认动作是「等你 yes」。
5. **你拍板后再改**。同意的条目由你（或你明确授权 Bot）改；拒绝的写入变更日志，避免下周重复提。
6. **记一笔变更日志**。日期、采纳/搁置、对应 Changelog 链接，方便回溯。

## 提示词

```text
你是我的首席 Bot，本周只做「功能对照 → 提案」，不要改任何 Routine。

硬规矩：
1. 只读官方来源：https://x.ai/changelog/bot 以及 docs.x.ai 里的 Grok Bot 文档；不要拿论坛或二手帖当依据。
2. 对照过去约七天（或我说的起止日期）的更新，挑与我现有 Routine / 连接器 / Auto-review 相关的条目。
3. 先让我确认你列出的 Routine 清单；清单未确认前不要写提案。
4. 输出一张「仅提案」表：功能名、版本与官方链接、可能相关的 Routine、建议动作、风险、需要我确认的点。灰度或尚未全量的功能必须标出。
5. 禁止：编辑、暂停、删除、新建 Routine；禁止改 Auto-review 规则；禁止连接或断开插件。除非我在本轮明确说「执行第 N 条」。
6. 文末附一段变更日志草稿（今天日期 + 提案摘要），等我采纳后再写入长期记录。

我的 Routine 概况（可改）：
- 名称 / 触发 / 主要连接器 / 最近痛点：……
```

## 产出

一张「仅提案」对照表，外加可选的变更日志草稿。表里每一行都应能点回官方 Changelog 段落；没有你的明确 yes，配置保持原样。

## 注意事项

- **只提案，不代改。** 保存/编辑 Routine 本身在新版本里可能不再被 Auto-review 当成高风险，但这不等于允许无人值守改生产流程。
- **官方优先。** 社区帖只能当灵感；版本号、上限、连接器行为以 Changelog 为准。
- **标清灰度。** 标注「需 0.75.x+」或「Teams / Enterprise only」的条目，不要当成人人可开。
- **留变更日志。** 下周对照时先看上周搁置项，避免反复提同一条。
